Easy Memory

Per-repo memory for Claude Code. After each answer it saves a note. Before your next prompt it hands the agent a short index of the notes that match. The agent can ignore the index or open one note.

  • Local — one Python file, standard library only. No model calls, no network, nothing leaves your machine.
  • Hooks and MCP — a Stop hook, a prompt hook, and a stdio MCP server with four tools.
  • Measured on yourself — a per-repo switch alternates memory on and off by day, and a report compares the two.

View the source on GitHub

What it is

Coding agents pay again for what an earlier session already found out. They read the same files again, and long sessions carry every old tool result forward. Easy Memory saves what a session concluded and gives it to the next session that needs it. The goal is fewer model tokens at the same accuracy.

  • Notes are data, not instructions. The index says so, and note text is quoted so it cannot leave its frame.
  • A hook never blocks you. On any error a hook exits 0, adds nothing and writes one line to a local log.
  • Nothing is written inside your repo. Notes live under ~/.easy-memory/ (files 0600, folders 0700).

Terms: a note is one saved answer with its question and the repo files it cited. The index is up to 5 lines about matching notes. The switch is the per-repo state: on, off or auto.

Context

This continues easy-context-mcp, which was retired on 2026-10-23. Code search (vectors plus a symbol graph) did not beat plain grep in any test. Memory between sessions was the first idea that did. Three experiments came before any product code.

#QuestionResult
01Does memory from the last session cut tokens on a follow-up?Yes. The previous final answer cut tokens by 58% at the same accuracy and caught a renamed method. Resume was misled.
02Does it still work when saving, choosing and delivering memory are automatic?Risk. It cut tokens by 35% on one repo and added 4% on the other, about 15% saved overall. Stale memory misled 0 runs. The picker was the weak part.
03Can more precise injection save tokens on both repos?Go for a prototype. The index method (list notes, the agent opens one) cut tokens by 29% and 27%. Accuracy was the same.

The prototype is the index method from experiment 03. Raw agent answers from the experiments stay local, because they quote private source code.

How it works

  • Stop hook saves one note per turn: the question, the answer, the time, and the sha256 of each repo file the answer cited.
  • Prompt hook scores each note against your prompt. It adds at most 5 lines in a frame of at most 2,500 characters, and flags cited files as CHANGED: or DELETED:.
  • MCP server offers memory_search, memory_read, memory_list and memory_forget. Ids are checked, and nothing outside the notes folder can be read or deleted.
  • Repo key: git worktrees of one repo share one store.

Install

Clone the repo, then run three commands from that clone. Run them from the main checkout, never from a git worktree. The hook commands keep an absolute path.

1. Get the code

git clone git@github.com:thunderkds/easy-memory-mcp.git
cd easy-memory-mcp
python3 -m unittest discover -s tests

Pass: the last line reads OK.

2. Preview the change

python3 easy_memory.py install --dry-run

It prints a diff of your user-level Claude Code settings ($CLAUDE_CONFIG_DIR/settings.json, else ~/.claude/) and the claude mcp add command. It writes nothing.

3. Install

python3 easy_memory.py install

It copies the settings file to settings.json.easy-memory.bak.<time>. It then adds a Stop hook (10 s timeout), a prompt hook (5 s timeout) and the allow rule mcp__easy-memory. It registers the MCP server with claude mcp add --scope user. Run it twice and the second run changes nothing.

Check: claude mcp list shows easy-memory connected. If claude is not on your PATH, the hooks still install and the manual command is printed.

Use it

CommandWhat it does
switchPrints the state for this repo and what it means today.
switch on|off|autoSets it. auto is the default: on for even days, off for odd days since 1970-01-01. The Stop hook saves notes in every state.
reportCompares sessions with memory on and off from Claude's own session logs: sessions, median tokens, median turns, and how often a listed note was opened.
install / uninstallAdd or remove the hooks, the allow rule and the MCP server.
  • The headline token count is input + cache creation + cache read + output, as the experiments counted it. A second column shows input + output only.
  • With fewer than 10 sessions in either group, the report says too few sessions to compare and prints no percentage.
  • Every prompt leaves one line in ~/.easy-memory/<repo key>/prompts.log: time, session id, configured and effective state, and whether an index was added.

Remove it

Roll back if Claude Code shows a hook error on every prompt, prompts feel slow (about 1 s or more), the MCP server fails in claude mcp list, or opening a note triggers a permission prompt.

python3 easy_memory.py uninstall            # removes both hooks and the allow rule
claude mcp remove --scope user easy-memory  # only if uninstall printed it as a manual step
python3 easy_memory.py uninstall --purge    # also deletes ~/.easy-memory (prints the size first)

If the settings file is still wrong, copy the newest settings.json.easy-memory.bak.<time> back over it. Check: grep easy_memory "$CLAUDE_CONFIG_DIR/settings.json" prints nothing.

Known limits

LimitDetailStatus
Notes pile upThe prompt hook gets about 1 ms slower per saved note. It passes the 1 s limit at roughly 1,000 to 3,000 notes. At about 5 s the hook timeout kills it and the index silently disappears.open
Big transcriptsThe Stop hook reads the whole transcript into memory. A 400 MB transcript used 808 MB.open
Non-git folderThe background weights build has no cap when Claude Code starts in a folder that is not a git repo.open
Clear textAnswers and prompts are saved unencrypted (mode 0600). Do not use it where answers can hold secrets you would not keep on disk.accepted
Permission promptThe live check that opening a note causes no permission prompt has not run. It needs your own credentials.to run

How it was built

Easy Memory was built with Easy Kit, the supervisor pipeline in this family. The work ran on the extended track, because it was Complexity C2, touched user settings, and needed more than one agent.

  • Plan — a PRD, a brainstorm of three paths (the single-file prototype won) and nine task guides, kept in Linear.
  • Build — one isolated sub-agent per task, test first, each with a before-and-after demonstration.
  • Review and verify — each task was reviewed and run by hand in temporary folders before it merged. The final task was an independent QA agent.
  • Ship — a release plan, a rollback plan and a runbook. You run the install steps yourself.

Its sibling, Easy Verifier, is the offline scoring MCP the project used as a dev tool.
