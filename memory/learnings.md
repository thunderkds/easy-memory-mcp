## Patterns

- 2026-10-28 — Board setup without a terminal: `board_sync.py init` needs `/dev/tty`. Call `board_sync.init(root, ask, make_adapter, env, out, err)` from Python with a scripted `ask`. Create issues in dependency order with `create --guide`, then rewrite forward `Txxx` references to the new IDs and push each with `update --guide` (`scripts/board_sync.py`).

- 2026-10-28 — Store folders: `os.makedirs`/`mkdir(mode=)` obey the umask and race under concurrent writers; create with explicit `chmod` and tolerate `FileExistsError` (`easy_memory.py` `_private_dir`, HUN-74).
- 2026-10-28 — Hook stubs and later hook handlers must write nothing to stdout (it joins the prompt) and must catch argparse exit 2 to keep exit 0 (NFR-004) (`easy_memory.py`).
- 2026-10-28 — Stop hook (HUN-75): bare-name citations resolve through `git ls-files` only when unique; paths are `realpath`-checked against the repo root so `..` and escaping symlinks are rejected; citation regex length-capped to avoid quadratic scan (`easy_memory.py` `cited_files`). `hook-stop` swallows argparse exit 2 and always exits 0; p95 0.063 s on 7,000 files.
- 2026-10-28 — Weights (HUN-76): tests that patch `subprocess.Popen` also patch git calls; use a spy that intercepts only `build-weights` argv. Experiment 03 answers live only in git history (`6452883`); extract them outside the repo and pass `EASY_MEMORY_EXP03_DIR` to `tests/parity_t003.py`. Known gap: two callers can both replace the same stale build lock.
- 2026-10-28 — Prompt hook (HUN-77): note text is untrusted. Index fields are JSON-quoted, whitespace-collapsed, control/format characters stripped, `<`/`>` replaced by `‹`/`›`, ids and cited paths regex-checked; p95 0.238 s on Project B with 200 notes. A test that calls a hook through `main()` must set a temp `EASY_MEMORY_HOME` and stdin, even for a stub (a stub test wrote to the real `~/.easy-memory/hook.log` once; removed).
- 2026-10-28 — Switch (HUN-78): `auto` is on when days since 1970-01-01 are even; `_today()` is the test seam. `hook-prompt` reads the switch first and logs one `prompts.log` line per run with readable input (none for bad stdin: no repo to name); a log failure goes to `hook.log` only. `hook-stop` ignores the switch.
- 2026-10-28 — Report (HUN-80): Claude session JSONL writes one API reply as several lines with the same `message.id`; count once with the largest value per token field. Headline tokens = input + cache creation + cache read + output, as experiments 01 to 03 counted; `in+out` is a separate column. Field names checked against a real log (`sessionId`, `message.id`, `message.usage.*`, `tool_use.name`); sessions are joined to `prompts.log` by session id. Parallel tasks both edit the stub-test tuple in `tests/test_t001_store.py`: keep both sides on merge.
- 2026-10-28 — Install (HUN-79): hooks go into `$CLAUDE_CONFIG_DIR/settings.json` (here `~/.claude-personal`) as `<sys.executable> <abs easy_memory.py> hook-stop|hook-prompt`, timeouts 10 s / 5 s; backup `<file>.easy-memory.bak.<UTC>`; indent and final newline kept, but a hand-written one-line array is expanded on rewrite (JSON-equal, not byte-equal). Run the real `install` from the MAIN checkout, not a worktree, because the command holds an absolute path. `--purge` only deletes a resolved folder named `.easy-memory*`. A test that calls a stub through `main([name])` becomes dangerous once the stub edits real user files: skip or sandbox it in the same commit.
- 2026-10-28 — MCP server (HUN-81): hand-written stdio JSON-RPC (`serve`), four tools; `memory_search` reuses the hook's index lines but only reads existing weights (no background build from the server). `install` runs `claude mcp add --scope user easy-memory -- <python> <path> serve` and adds allow rule `mcp__easy-memory`; tests must put `tests/fake_claude.py` first on PATH (a real `claude` on PATH ran during one test run). AC6 (live `claude -p` permission test A3) stays PENDING for the user; fallback is Read of the note path with the store in `permissions.additionalDirectories`, and the index header still says the agent may Read the note file.
- 2026-10-28 — QA (HUN-82): full cycle, modes, no-network (socket shim and `strace`), garbage stdin, repo tree hash and clean-clone suite all pass (307 tests); Project B p95 0.212 s (`hook-prompt`, 200 notes) and 0.066 s (`hook-stop`). Open defects, no follow-up tasks yet: D1 `hook-prompt` time grows ~1 ms per saved note, so NFR-001 (1 s) breaks at ~1,000-3,000 notes and the hook timeout (5 s) at ~5,000 (repro `HUN82_GROWTH_PROBE=1 python3 -m unittest tests.test_t009_smoke.StoreGrowthProbeTest`); D2 `hook-stop` reads the whole transcript into memory (400 MB file -> 808 MB RSS); D3 background weights build has no cap in a non-git cwd; D4 answers and prompts are stored in clear text (PRD A6). Real `claude -p` check (HUN-81 AC6) is still the user's.
- 2026-10-29 — Redaction regex: a private key block needs one whole-text DOTALL regex with the fallback `|.*` (fail closed). The `|\Z` form was quadratic (7 s at 224 KB). Bound name parts, restrict `NAME: value` to values of 8+ characters, and add a look-behind to `sk-`. Source: round 2 of `BRAINSTORMING_LOG_v0.2.md`. As built (HUN-85): a substring gate skips each pattern whose needle is absent, assignment `=`/`:` are one regex, name tails are possessive (`{0,32}+`, needs Python 3.11+), and `[REDACTED:secret_assignment]` is never re-redacted (idempotent). Accepted over-redaction: `max_tokens=4096`. Open P3: `log_hook_error` logs `str(err)`; future code that puts input text in an exception would leak it to `hook.log` (log the type name only).
- 2026-10-29 — Package split: a `patch.object(easy_memory, ...)` left on the shim passes without testing anything. 13 of 24 sites must point at the defining module. Guard with a test on `vars()` of the target module. Use `easy_memory_core/`, not `easy_memory/` (it would shadow the shim).

## Gotchas

### 2026-10-31 — The merge gate blocks every merge while any task is In Progress
`pre_bash_block_unsafe_merge.py` refuses any command with `merge` in it (even `git merge-base`, `git merge-tree`) while any board row is In Progress or Ready for Review — not only the task being merged. Tasks held by a merge gate (Gate 2a: HUN-137/138/139) therefore block unrelated merges. Fix used: park verified-but-held tasks in Todo with a Linear comment naming the merge condition (`report` shows ≥10 sessions per group; then rebase, re-run suite + verify, merge). A kit task should scope the gate to the merged task.

### 2026-10-31 — security-review and verify skills cannot target a task worktree
In this repo layout (one worktree per task) the built-in `security-review` diffs the main checkout (`main` vs `origin/main`), and sub-agents have no `verify` skill. Every reviewer redid the review by hand on `git diff main...HEAD` in the worktree, and verify ran as a real run against a throwaway `EASY_MEMORY_HOME`. Write the active-task state file first so the trace is tagged.

### 2026-10-31 — Stop hook re-blocks on expired untagged evidence (kit 04b019a)
`stop_auto_mode_check.py` counts untagged `Skill` records only from the last 6 h, and checks a task whose worktree review file says `Mode: auto` even when the board row is Todo. Result: every stop of a normal session was blocked for hours. Kit task T186 ("paused means paused") is set up in `../wt-t186`; run it from a kit session, then update the kit here.
